## Getting Started

1. Run `npm install`
2. Copy `.env.example` to `.env.development` and set `VITE_MOCK_AUTH=true` to sign in with the test code
3. Run `npm run dev`

## Environment variables

| Variable | Values | What it does |
| --- | --- | --- |
| `VITE_MOCK_AUTH` | `true` / anything else | Test mode for sign-in, dev server only (see below). |

## Test mode (`VITE_MOCK_AUTH=true`)

The whole app needs an account (`REQUIRE_LOGIN` in `src/features/auth/config.ts`; set it to `false` to
browse without signing in again). In test mode:

- Every one-time code (phone or email verification, phone-code sign-in, password reset) is the test code
  **123456**. Only 123456 works; wrong codes, expiry and the lockout behave as in production.
- The demo customer and vendors also sign in with a password: the demo password shown in the demo panel
  (defined in `src/features/auth/testMode.ts`, test mode only). The rider and staff use phone codes.
- The OTP screen shows "Test mode: use code 123456" with an "Autofill test code" button.
- The login screen lists the demo accounts. "Use this account" fills in the sign-in form:

  | Account | Sign in with |
  | --- | --- |
  | Customer | aisha@example.com + demo password |
  | Provider (service vendor) | 0800 000 0002 (or bala@example.com) + demo password |
  | Provider (retail vendor) | 0800 000 0003 (or fatima@example.com) + demo password |
  | Rider | 0800 000 0004 + code |
  | Super admin | 0800 000 0010 + code |
  | Verifier, Support, Moderator, Analyst admins | 0800 000 0011 to 0800 000 0014 + code |

  All demo numbers and emails are fake. Admins follow the usual staff session rules (shorter sessions,
  audit log entries).
- New accounts go through the normal signup: Welcome → Create account → role picker → that role's form
  (customers: name, email, password; providers: name, phone, email, location, password, terms; riders:
  phone code) → verification with the test code → onboarding.
- "Reset demo data" (in the dev banner and the demo accounts panel) restores the seeded accounts and
  signs you out.

### Production safety

The test code is accepted only when `VITE_MOCK_AUTH` is exactly `"true"` in the dev server. A production
build (`npm run build`):

- refuses to run while `VITE_MOCK_AUTH=true`;
- fails if the test code, the demo password, or any dev-only banner or panel is found in the bundle.
