# Gwani — Project Overview

> A complete write-up of the `new-marketplace` project: what it is, how it's built, how every part works, and what's missing before it could be a real product.

---

## 1. What this project is

**Gwani** is a **front-end prototype of a local-services marketplace** for **Minna, Niger State, Nigeria**. It connects customers with verified local tradespeople (plumbers, tailors, electricians, dispatch riders). Prices are in Naira (₦), locations are LGAs and neighbourhoods around Minna, and the copy is written for that audience (for example aso-ebi, Ankara, NEPA office, borehole pumps).

The app has **two modes** in one single-page app:

| Mode | URL prefix | Who uses it | What they do |
|---|---|---|---|
| **Customer** | `/` | People who need a job done | Browse and search vendors, view a vendor profile, send a job request, track job progress, see bookings and messages |
| **Vendor ("Pro") portal** | `/pro` | Tradespeople | Respond to incoming requests with quotes, view their calendar, manage their service catalogue, track earnings and withdraw funds |

Users can switch between the two modes from the sidebar, the Profile page, or the vendor header.

**Origin:** The code was generated by **[Magic Patterns](https://magicpatterns.com)**, an AI design-to-code tool, from the design [mjx4vmtp21actyjkjmnueu](https://www.magicpatterns.com/c/mjx4vmtp21actyjkjmnueu). The package name is still `magic-patterns-vite-template` and the HTML title is "Service Booking App Design".

**Nature:** This is a **UI prototype with no backend**. All data is hard-coded mock data in `src/data/`. The app keeps state in React memory only, so everything resets when the page reloads. Network actions such as sending a quote or withdrawing money are faked with `setTimeout`.

## 4. Application architecture

### 4.1 Boot sequence

1. `index.html` loads `/src/index.tsx`.
2. `index.tsx` imports `index.css` and renders `<App />` into `#root`.
3. `App.tsx` wraps everything in:
   ```
   <JobsProvider>              ← customer job state
     <VendorPortalProvider>    ← vendor requests + services state
       <BrowserRouter>
         <Routes>…</Routes>
   ```

### 4.2 Route table (`src/App.tsx`)

| Path | Layout | Page | Purpose |
|---|---|---|---|
| `/` | CustomerShell | `Home` | Greeting, search, category filter, vendor list |
| `/vendor/:vendorId` | CustomerShell | `VendorDetail` | Vendor profile, gallery, stats, CTA |
| `/vendor/:vendorId/request` | CustomerShell | `RequestJob` | Job request form |
| `/jobs/:jobId` | CustomerShell | `JobStatus` | Progress stepper, quote, report issue |
| `/bookings` | CustomerShell | `Bookings` | Active and completed jobs |
| `/inbox` | CustomerShell | `Inbox` | Message thread list |
| `/profile` | CustomerShell | `Profile` | User details and a link to the vendor portal |
| `*` | CustomerShell | `NotFound` | Fallback |
| `/pro` (index) | VendorShell | `vendor/Requests` | Vendor dashboard and incoming requests |
| `/pro/calendar` | VendorShell | `vendor/Calendar` | Week schedule |
| `/pro/catalogue` | VendorShell | `vendor/Catalogue` | Services offered |
| `/pro/earnings` | VendorShell | `vendor/Earnings` | Revenue chart, transactions, withdraw |

### 4.3 Layout: `AppShell`

`AppShell` is a single layout component used by both modes. It takes `navItems`, `homeTo`, an optional `modeLabel`, `account` (name and subtitle) and `switchLink`.

- **Desktop (`lg` and up):** a fixed 256px dark-pine sidebar with the "G / Gwani" logo, nav links, an account card and a "switch mode" button. Content is offset with `lg:pl-64`.
- **Mobile:** a fixed 4-column bottom tab bar that respects `safe-area-inset-bottom`. Content has `pb-24` to clear it.
- A `NavItem`'s active state comes from its own `match(pathname)` function, so for example the Home tab stays active on `/vendor/...`.
- Nav items can have a `badge` count. It shows as a pill on desktop and a dot on mobile.

The two wrappers:
- **`CustomerShell`** shows an unread-message badge on Inbox (count of `messageThreads` with `unread: true`). The account is Aisha Mohammed. The switch link goes to `/pro`.
- **`VendorShell`** shows a pending-request badge on Requests (count of requests with `status === 'awaiting_quote'`, updated live from context). Its mode label is "Vendor" and the account is Bala Plumbing. The switch link goes to `/`.

### 4.4 State management

There's no Redux or server state. The app uses two React Contexts seeded from the mock data:

**`JobsContext`** (`src/contexts/JobsContext.tsx`)
- State: `jobs: Job[]` (seeded from `data/jobs.ts`)
- `getJob(id)`: find a job by id
- `addJob(input: NewJobInput)`: creates a job with id `max(existing ids) + 1`, `stage: 'requested'`, `quote: null`, `createdAt: now`, and adds it to the front of the list
- Hook: `useJobs()`. It throws if used outside the provider.

**`VendorPortalContext`** (`src/contexts/VendorPortalContext.tsx`)
- State: `requests: VendorRequest[]` and `services: ServiceItem[]`
- `sendQuote(id, amount, note)`: sets the status to `quoted` and stores the quote and note
- `declineRequest(id)`: sets the status to `declined`
- `restoreRequest(id)`: resets to `awaiting_quote` and clears the quote and note (this is the "Undo")
- `addService(input)`: appends a service with id `s${Date.now()}` and `photo: null`
- `removeService(id)`
- Hook: `useVendorPortal()`

Everything else is either read directly from `src/data/*` as static data (vendors, categories, messages, user, appointments, transactions, vendor account) or is local component state.

> **Important:** The two contexts are **not connected**. A customer's job request does not create a vendor request, and a vendor's quote does not update any customer job. The customer side and the vendor side are separate demos that share only the mock-data theme (for example, "Aisha M." / "Kitchen tap leak" appears on both sides).

## 5. Domain model (`src/types/`)

- **`Appointment`**: `id, customerName, service, area, start (ISO), durationHours, status`
- **`AppointmentStatusInfo`**: `{ label, badgeClass, blockClass }`
- **`EarningTransaction`**: `id, customerName, service, date, amount`
- **`WeeklyEarning`**: `{ label, total }`
- **`VendorAccount`**: `vendorId, businessName, tier, subscriptionPrice, renewsOn, payoutAccount, availableBalance, nextPayout, profileCompletion, profileHint, rating, jobsCompleted, slaMinutes, feeRate, workingHours`

### Navigation (`navigation.ts`)

- **`NavItem`**: `{ to, label, icon: LucideIcon, match(path) → boolean, badge? }`

## 7. Feature walkthrough

### 7.1 Customer mode

**Home (`/`)**
- Green header: "Hi, Aisha 👋" with the location.
- A search box that matches vendor name, tagline, about text and category label (case-insensitive).
- 4 category toggle buttons. Clicking an active one clears the filter.
- The section title changes between "Trending near you", "Results" and "{Category} near you".
- "Clear filters" appears when a filter or search is active.
- Results show as a responsive grid of `VendorCard`s (1, 2 or 3 columns), or an empty state reading "No verified vendors match that yet".

**Vendor detail (`/vendor/:vendorId`)**
- Header: name, category · LGA, rating and review count, verification badge, and a back link to Home.
- Main image with clickable thumbnails when the gallery has more than one photo.
- About card with years of experience, description and distance.
- Sticky side panel with price-range and response-time tiles and a **"Send job request"** button. The note underneath says the customer gets a fixed quote before anything is booked.
- Shows `NotFound` if the id is unknown.

**Request a job (`/vendor/:vendorId/request`)**
- Uses the `useJobRequestForm` hook:
  - Fields: description, date (defaults to tomorrow, and past dates are blocked with `min`), time (11 hourly slots from 08:00 to 18:00, default 10:00) and address (prefilled with the user's saved address).
  - Up to **4 photos** from a hidden file input. Previews use `URL.createObjectURL`, and each photo can be removed.
  - Validation: description at least 10 characters, a date is required, an address is required. Errors clear as the user types.
- On submit: a 700 ms fake delay with a spinner, then `addJob(...)`, then a redirect to `/jobs/{newId}` (with `replace`).
- Desktop side panel: vendor summary with typical price, response time and a "Nothing is booked until you accept it" note.

**Job status (`/jobs/:jobId`)**
- A `JobStepper` showing the 5 stages. Completed stages get a clay dot, the current stage gets a larger mustard dot with a ring, and upcoming stages are grey. There's screen-reader text for each state.
- Job details: description, address and photos.
- Tiles: quote (or "Pending" / "Awaiting quote") and scheduled day and time.
- A "Message vendor" link that goes to `/inbox`. There's no chat view.
- A "Report an issue" button that expands an animated form. It fakes a 600 ms send, then shows "Report received… support will reach out within 2 hours".

**Bookings (`/bookings`)**
- Header: "N active · M completed".
- Jobs grouped into Active (every stage except completed) and Completed, each row showing the vendor photo, name, job number, date and time, the description (from `md` up) and a stage badge. Rows link to the job status page.
- Empty state: "No bookings yet" with a "Find a vendor" link.

**Inbox (`/inbox`)**
- A list of message threads with vendor avatar, name, time, preview (bold when unread), job number and an unread dot. Each thread links to its **job** page. There's no conversation screen.

**Profile (`/profile`)**
- A definition list: phone, saved address, languages, and jobs booked (a live count from context).
- A card linking to the Vendor portal.

### 7.2 Vendor ("Pro") mode

**Requests (`/pro`)**, the vendor dashboard
- Header: business name, "Vendor mode", a mustard "Subscription active · Trade tier" badge, and a "Customer" switch button on mobile.
- An SLA banner when there are pending requests: "N new requests — respond within 15 min to keep your fast-response badge".
- A **`RequestCard`** for each pending request:
  - Default view: **Send quote** / **Decline** buttons.
  - Quote view (animated with framer-motion): a ₦ amount input that auto-formats with thousands separators, an optional note, and validation of at least ₦500. The submit button shows "Send ₦6,500". Sending takes 600 ms, then calls `sendQuote`.
  - Decline immediately calls `declineRequest`.
- Empty state: "You're all caught up".
- A **Recent** list of quoted and declined requests. Quoted rows show the amount. Declined rows have an **Undo** button (`restoreRequest`).
- Side panel: a last-7-days earnings tile (links to Earnings), a rating tile, and a **"Next up"** card for the soonest appointment that isn't completed and hasn't finished yet, with a link to the calendar.

**Calendar (`/pro/calendar`)**
- Header: "N jobs this week · M still to do".
- Week navigation (Monday-based) with Today, previous and next buttons, a date-range title and working hours.
- **Mobile:** `DayAgenda`, a 7-day picker (dot marks days with jobs, today is outlined) plus an ordered agenda for the selected day with time, service, status badge, customer, duration and area. Empty day: "No jobs booked · You're open for requests".
- **Desktop:** `WeekGrid`, a time grid from 8 AM to 6 PM (60 px per hour) with 7 day columns. Appointments are absolutely positioned blocks coloured by status. Blocks show more detail (service, area) when they're tall enough. Today's column is tinted. A legend sits below.

**Catalogue (`/pro/catalogue`)**, titled "My services"
- Header with a profile-completion progress bar (70%) and a hint.
- "N services listed" plus an **Add service** button that opens an animated `AddServiceForm`:
  - Name, From (₦), To (₦) (auto-formatted digits only) and a Typical duration select.
  - Validation: name required, min and max required, max must be at least min.
- Service cards in a 2-column grid from `md` up, showing photo (or a wrench placeholder plus "Add a photo to stand out"), price range, duration and a trash button to remove the service.
- Empty state: "No services yet — Customers can only request jobs you list here."

**Earnings (`/pro/earnings`)**
- A toggle between **7 days** and **8 weeks**.
  - 7 days: `lastNDays()` groups `earningTransactions` by day (the last bar is "Today" and highlighted in clay). The headline is the 7-day total, with a % change against the previous week's total from `weeklyEarnings`, shown with an up or down trend icon.
  - 8 weeks: `weeklyEarnings` with the latest week highlighted. The headline is the 8-week total.
- `EarningsChart`: a Recharts bar chart with a custom tooltip, a Y axis in "k" units, and pine and clay bars.
- **Completed jobs** list showing the net amount after the 5% fee (`netAmount`) and "of ₦gross".
- Side panel:
  - **`WithdrawCard`**: the available balance and auto-payout date and account. The flow goes Withdraw now → confirm → 800 ms "Sending…" → done ("₦X on its way…"), and the balance drops to ₦0. This is local state only, so it resets when you leave the page.
  - A subscription card: Trade tier, ₦2,500/month, renewal date, "Active".

## 9. Design system

Defined in `tailwind.config.js` and used throughout as Tailwind classes:

| Token | Hex | Used for |
|---|---|---|
| `cream` | `#FAF6EE` | Page background |
| `sand` | `#F1ECDF` | Tiles, secondary buttons |
| `line` | `#E7DECB` | Borders and dividers |
| `ink` | `#1C1B18` | Primary text |
| `muted` | `#6B665B` | Secondary text |
| `pine` / `pine-deep` | `#1F4B4D` / `#163A3C` | Brand: headers, sidebar, primary buttons |
| `clay` / `clay-dark` / `clay-soft` | `#CF5A2E` / `#A8441D` / `#FBEDE6` | Main CTAs, errors, highlights |
| `mustard` / `mustard-dark` | `#D9A933` / `#8A6410` | Badges, current step, logo, withdraw |

- **Typography:** Manrope. Headings are extrabold with tight tracking, and section labels are small uppercase text with wide tracking.
- **Shapes:** rounded-xl or rounded-2xl cards and buttons with 1px `line` borders. There are no drop shadows.
- **Motion:** short 150–200 ms transitions with the easing `[0.23, 1, 0.32, 1]`, and a press effect of `active:scale-[0.98]`.
- **Responsive:** mobile-first. The `lg` breakpoint switches to the sidebar layout and two-column pages with sticky side panels.
- **Accessibility:** a good baseline. It uses semantic landmarks, `aria-current`, `aria-pressed`, `aria-invalid` and `aria-describedby`, `role="status"` for confirmations, `sr-only` labels, visible `focus-visible` rings, `aria-hidden` on decorative icons, and a `progressbar` role.
- There is **no dark mode**.

## 11. Known issues, gaps and quirks

**Configuration and housekeeping**
1. `src/package.json` is a leftover Magic Patterns manifest with different versions (e.g. react-router-dom 6.30.2, lucide-react 0.577.0) and packages the project doesn't use (`@radix-ui/react-icons`, `tailwind-merge`). The build ignores it, and it could be deleted.
2. `index.html` links a favicon at `/vite.svg`, but that file doesn't exist in `public/`, so browsers get a 404.
3. The title "Service Booking App Design" and the package name `magic-patterns-vite-template` don't match the Gwani brand.
4. `@emotion/react` is installed but unused.
5. `autoprefixer` and `postcss` are pinned to `latest`, which isn't reproducible.
6. The `import React` lines aren't needed (see §10).

**Functional gaps (prototype limits)**
7. **No backend or persistence.** All state is lost on reload. There's no authentication, and there's one hard-coded customer and one hard-coded vendor.
8. **The customer and vendor sides are disconnected** (see §4.4). A new job request never appears in the vendor's Requests, and quotes never reach the customer.
9. New jobs stay at `requested` forever. There's no UI to accept a quote or move a job through its stages.
10. There's no messaging screen. Inbox rows and "Message vendor" only link to the job page or the inbox list, and unread state never changes.
11. Uploaded photos are blob URLs. They're never revoked (`URL.revokeObjectURL`) and they stop working after a reload.
12. `WithdrawCard`'s balance is component state, so navigating away and back restores ₦32,700.
13. Calendar appointments and earnings aren't editable and aren't linked to requests or services.
14. The vendor's "Add a photo" hint has no upload path. New services always have `photo: null`.
15. Reports from "Report an issue" aren't stored anywhere.

**Logic edge cases**
16. `addJob` computes the next id with `Math.max(...ids) + 1`. With an empty job list this gives `-Infinity + 1`.
17. The Earnings "% vs previous week" compares a total built from transactions (last 7 days) with a hard-coded weekly figure (`weeklyEarnings[length-2]`). These are different data sources, so the percentage isn't meaningful.
18. `WeekGrid` only handles 8 AM–6 PM. An appointment starting at or after 18:00 would get a negative height, and one before 08:00 is clamped to the top of the grid.
19. The `setTimeout`s in `RequestCard`, `RequestJob`, `JobStatus` and `WithdrawCard` aren't cleared on unmount.
20. `useJobRequestForm` recalculates `scheduledAt` on every render (harmless). An invalid date string would throw in `toISOString()`.
21. There's no catch-all route under `/pro`. Unknown `/pro/...` paths fall through to the customer `NotFound`.

## 12. Suggested next steps

1. **Clean-up:** remove the unused `React` imports, delete `src/package.json`, add a favicon, rename the package and title, and remove `@emotion/react`.
2. **Version control:** `git init` and make an initial commit.
3. **Backend:** add an API and database (for example Supabase, Firebase or a Node/Express service) for users, vendors, jobs, quotes, messages and payouts, and replace `src/data/*` with fetches (for example with TanStack Query).
4. **Unify the job lifecycle:** make a customer request create a vendor request, make a vendor quote update the job to `quoted`, add customer **accept/decline quote**, and let the vendor mark jobs in progress or complete. This would also feed the calendar and earnings.
5. **Auth and roles:** use phone and OTP login (a good fit for the Nigerian market) with customer and vendor roles instead of a free mode switch.
6. **Messaging:** add real chat threads per job.
7. **Payments:** integrate a Nigerian payment provider (e.g. Paystack or Flutterwave) for payouts, subscriptions and escrow.
8. **Quality:** add Vitest and React Testing Library tests (form validation, `lastNDays`, `netAmount`, the stepper), add `tsc --noEmit` to CI, and split the bundle per route with `React.lazy`.
